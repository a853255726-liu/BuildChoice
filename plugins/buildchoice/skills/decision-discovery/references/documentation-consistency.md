# 文档与实现一致性

用户要求核对或更新说明，或本次修改影响已有用户说明所描述的行为时使用。以用户指定主题或当前改动为边界，定位相关说明；无需为每次代码修改盘点整套文档或创建新文档。

<!-- buildchoice-guidance:topic:documentation:start -->
维护版本：`intent-alignment.v1`。

判断用户能否依据相关说明正确理解并完成操作；命令、默认值、结果与限制须对应实际依据。区分实现、要求和未来计划，不能靠修改说明把需求偏差说成已解决。只查相关范围，不全量扫描或擅改业务行为。
<!-- buildchoice-guidance:topic:documentation:end -->

将有关命令、参数、默认值、操作结果和限制，与对应实现和已有运行证据核对。说明到实现、实现到说明的检查都限于本次范围；标出具体位置与依据。特别区分当前实现、用户要求和未来计划：代码可以证明当前怎样实现，不能据此覆盖用户原本的要求或已确认决定。

发现差异后先判断哪一方需要修正。不能为了让文档吻合而擅自改变行为，也不能把偏离需求的实现写进文档后当作问题已解决。可自行查明的先查；重要业务取舍才问用户。

用户只要求审查或提案时报告具体差异；已有修改授权则直接完成相关修正。生成文档应修改其真正来源并按原流程生成。沿用项目的语言、目录、发布时机和检查命令；纯文字修正不因此运行整套构建，相关结果仍有效时复用。

发现并入已有反馈，只报告有影响的差异，不额外生成固定报告、批准轮次或全量核对表。

改写自 OpenAI Agents SDK 的 docs-sync；移除了 SDK 专用路径、英语限定、默认分支假设和固定构建命令。见[来源、版本与许可证](upstream-sources.md)。
