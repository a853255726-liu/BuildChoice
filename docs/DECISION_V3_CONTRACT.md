# BuildChoice · 决策引导接口契约

实现版本 `decision.v3`，0.6.0 增加可选 coverage 输入与响应覆盖摘要，移除模型字段。V3 默认关闭；audit.v1 的证据与复核含义不变。

## 用户路径

Hook 在工作区内提供真实轮次句柄，正则仅为正向提示。Agent 根据当前消息与对话判断是否实施开发；纯解释不筛选。实际开发时查阅相关约束，在同一次提取中提交候选和简短 coverage，不增加第二轮复核。

候选是 Agent 声明，yes/no/uncertain 保留不确定性。开发中出现新依赖时重筛；零候选继续；一次只激活一张卡。文件中的授权描述不能替代用户确认，卡片不替代宿主权限审批。

## 四状态

- INSPECT：相关来源可访问但尚未读取，先核实。
- ASK_NOW：当前或不确定依赖需要用户选择，只暂停受影响步骤。
- DEFER：当前不依赖且可独立推进；即将执行的高后果动作不能据此延后。
- PROCEED：当前适用的可信确认，或无冲突的明确约束及低影响工程细节。

显式风险与证据冲突优先于工程细节标记。排序依据风险、依赖与字段；无分类器或模型分数。

## 覆盖元数据

coverage 最多六项，每项理由最多 300 字符，状态为 resolved / candidate / not_applicable / uncertain。只记录相关维度，不为填满清单增加调用。不得将未查清内容标为“不适用”。

来源引用只用真实 source_id，服务端检查工作区、来源、引用定位与新鲜度。响应保留 Agent 声明并单独给出来源状态；`provenance=agent_declared`、`does_not_establish_completeness=true`。来源核验不能证明任务决策覆盖完整。

该元数据不进入 route，不授予许可，不单独触发问题。存入已有 V3 事件与幂等响应；任务状态读取最新记录，历史仍保留。不提交时 reported=false。

## 绑定与确认

真实 UserPromptSubmit 的会话、轮次及消息哈希生成短期随机句柄。首次任务绑定要求 task_text 与实际消息一致；句柄只由一个 MCP 会话认领。新目标按本轮用户原文建立新任务，既有任务重筛保留原 task_text。

0.8.3 的消息匹配统一 CRLF/CR/LF 与首尾空行，正文空格和缩进仍参与比较，会话/轮次身份不归一化。旧摘要与确认记录保持原值。Candidate 的选项 ID 唯一性与推荐项归属规则在初次筛选、修订及卡片生成中共用；非法修订不产生新版本。

筛选缓存使用内部版本化快照，公开 ScreenResponse 形状不变。来源或决定状态变化后不再将旧结果作为当前结果返回，而以 CACHED_SCREEN_STALE 要求重新读取和新键筛选。任务、句柄绑定、全部候选、覆盖事件及响应以一个事务提交；中断回滚后同一请求可重试，同键并发只提交一次。旧未完成标记只在匹配原请求摘要并取得写锁时恢复，不改写旧确认。

激活仅建立状态，不声称 UI 已显示。唯一待答卡、同会话、未过期且版本未变时，严格选项回复才成为 user_message_observed。解释、混合指令和自由表述不自动确认。修订追加版本并标记受影响实现待复核。

## 数据与升级

0.9 增加 memory.v1 项目决策记忆与 Candidate.memory_intent（reuse / change / uncertain，缺省 uncertain）。仅明确适用的当前长期规则可复用，Decision.memory 保存原确认来源；project_rule_reused 不生成本任务确认。敏感行为、冲突、改义、变化来源或意图改变继续核实，记忆状态纳入筛选快照。管理动作只接受真实 Hook 整条命令，旧历史保留。见[决策记忆](DECISION_MEMORY.md)。

coverage 复用事件表，不增加数据库版本。旧审计、确认及事件保留，已移除的模型历史字段不出现在当前响应中。旧模型设置可读为新的 V3 开关和有效期，写入时使用 config_version=2。

提取提示版本 `candidate-extractor-v3.5`。开发示例不是独立评测；规则与模拟 Hook 检查不能证明真实任务漏问率降低，真实宿主验收应另行报告。
