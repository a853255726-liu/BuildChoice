# BuildChoice · 决策引导接口契约

基线：`faa59babebbe47516d9f6040f6d4953d996ea654`。实现版本 `decision.v3`，新增能力默认关闭；旧四模式、模型阈值和 audit.v1 含义不变。

## 用户路径

开发前由主 Agent 读取相关约束，提取具有实质影响、用户归属、尚未明确、当前相关的候选。服务端核对来源并筛选。开发中仅在出现新的直接依赖时重筛；一次激活一张卡。零候选直接继续。

候选是主 Agent 的声明，不是独立事实；`yes/no/uncertain` 保留不确定性。模型仅提供字段信息缺口第二意见。个人信息外传、付费、不可逆删除和发布不因模型 PASS 获得授权。

## 四状态

- INSPECT：相关来源可访问但尚未读取，先核实，仍不授权受影响操作。
- ASK_NOW：需要用户决定且当前依赖，或依赖关系不明；只暂停受影响步骤。
- DEFER：当前不依赖且可以独立推进，保留触发阶段。不能用于已经准备执行的高后果动作。
- PROCEED：已有当前适用的可信确认，或确属低影响的工程细节，且证据无冲突。

显式风险与证据冲突优先于 Agent 的“工程细节”标记；NLI PASS 不能删除高影响候选。排序使用确定的风险、依赖与字段顺序，不把模型分数当概率。

## 输入与确认边界

`gate_screen_candidates` 接受完整请求对象。候选数量不迁就模型的 2/3 批次限制。来源仅引用真实账本 source_id；路径当前快照、引用定位和跨任务关系由服务端核对。

真实 UserPromptSubmit 的会话、轮次与消息哈希产生短期随机句柄；MCP 不能靠自报 session_id 获得绑定。首次绑定要求 task_text 与 Hook 观察的任务哈希一致，句柄只可由一个 MCP 会话认领。失效句柄保持未核验，不能伪装已确认。

激活卡片只表示状态已建立，不声称 UI 已显示。后续同宿主会话唯一待答卡，且版本未变时，严格的 A/B/C、选 A 或明确卡号形式才可由 Hook 记录为 user_message_observed。混合指令、自由表述、解释和不确定均不自动确认。

修订追加版本；旧确认保留历史，新确认生效时标记相关实现 needs_recheck。原生操作权限继续由宿主决定。

## 数据与发布

新增独立 V3 表，版本化迁移、备份和受限回退。默认只保存消息摘要、哈希和来源，不存整段聊天。旧 reviews 不作为用户确认。

新增 Skill 提取提示版本 `candidate-extractor-v3.1`。开发示例与冻结评测分开。真实主 Agent A/B/C 对照与规则单测分开报告；独立人工标注缺失时如实说明，不默认启用 V3。
