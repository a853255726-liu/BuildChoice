# 原生回复的关联与恢复

从 0.14.3 起，`buildchoice_context.reply_binding` 明确描述当前消息是否具备回复记账来源。`ready_to_interpret` 才可解释待答消息；`already_recorded` 复用回执；`awaiting_new_hook_message` 等待真实新消息。这个字段不判断用户的业务意图。

原生异步问题的点选可能作为当前执行中的消息到达。当前插件仅从受信任的 `UserPromptSubmit` 取得消息身份，不能保证宿主一定为每次异步回复触发这个事件。插件不从模型提交的表单包装补造可信来源。

可信 Hook 收到单题 `send_user_message_question_reply` 包装时，解析器要求结构唯一、题目与当前冻结题目相同、答案等于完整呈现选项。自定义回复、附加条件、多个问题、其他题目和旧选项不自动确认，继续保留真实原话供解释或澄清。原始消息摘要、当前卡片、会话、版本、过期和重复处理约束仍生效。

回复解释或指令记账缺少消息来源时，MCP 返回 `status=unbound`、`recorded=false`、稳定错误代码和 `recovery`。不应继续用旧句柄、拼接包装或换接口重试。不重新发送同一张卡；仅在确实需要持久化决定时，请用户发一条普通消息，让宿主产生新的 Hook 上下文。迟到的回复不会因恢复提示被自动写入。

Hook 异常会独立记录发生阶段和异常类型。提示策略失败时仍尝试决定消息关联；关联本身失败时给出明确的上下文提示。日志只包含时间、阶段、事件类别和异常类型，不包含消息、异常详情、文件路径或会话标识。

日志位于安装数据目录下的 `projects/<项目摘要>/diagnostics/hooks.jsonl`，单文件上限约 64 KiB，保留一份轮转。写日志失败不会中止任务或生成确认。没有 Hook 事件时不会产生诊断日志；这能辅助排查，不能证明宿主一定发送过事件。

本次验证使用隔离的合成消息和真实 MCP 传输；不将其表述为桌面端点选到 Hook 的完整验收。

宿主事件字段参考官方 [Hooks](https://learn.chatgpt.com/docs/hooks)。官方[异步工具说明](https://developers.openai.com/api/docs/guides/async-tool-calling)明确，提问函数的定义与返回方式由应用决定；这不构成本插件已取得可信回调的证明。
