# BuildChoice · 决策卡使用说明

BuildChoice 将影响数据、体验、成本或未来限制的工程方案整理成用户可理解的比较，普通实现细节由 Codex 自主处理。有依据的高风险选项可显示“风险提示”，用户可用字母或明确的自然语言选择。资料含糊或相互矛盾时先补查；详见[工程风险与证据边界](CANDIDATE_RISKS.md)。

决策卡帮助你确定会影响产品行为的选择，例如数据如何保存、谁能访问、是否自动执行。普通技术细节由 Codex 处理。安装后默认使用 Prompt-first，开启决策卡后，可在原对话中逐项选择方案。

## 开启与关闭

在仓库或已绑定的运行时目录执行：

~~~bash
python scripts/buildchoice_decisions.py pilot
python scripts/buildchoice_decisions.py settings
python scripts/buildchoice_decisions.py off
~~~

pilot 开启决策卡，settings 查看设置，off 关闭决策卡及项目决策记忆。Codex 原生设置中也可选择“决策引导：试用 / 关闭”。要完全关闭 BuildChoice，执行：

~~~bash
python scripts/buildchoice_settings.py off
~~~

恢复 Prompt-first 使用 python scripts/buildchoice_settings.py prompt。修改设置后，支持工具列表通知的 Codex 会刷新可用工具；更新插件代码后需重新连接 MCP 或重启 Codex。

## 在对话中使用

默认“工具集：日常”保留决定、上下文和文档能力。需要独立审计、长期记忆管理、代码关联或实验验证时，将原生设置中的工具集切为“完整”；命令行也可执行 `python scripts/buildchoice_decisions.py full`，恢复日常用 `core`。上下文仍可读取已有项目记忆。切换不会自动运行高级操作，也不会授予执行权限。

直接提出开发需求，例如“给现有项目加登录”。BuildChoice 结合当前需求、对话和项目资料检查是否存在需要你决定的选择。资料已有明确答案时先沿用；需要选择时，一次显示一张卡，说明选项、影响和建议。纯咨询、解释和已明确的普通修改照常进行。

你可以说“我选第二个”“就用核对后保存”，或回复卡面上的 A / B。完整方案名称和“按你推荐的来”也可用于明确选择。对于“采用核对后保存，请继续完成页面”等表达，Codex 可结合原话解释所选方案，并标记该解释来源。问句、否定、多方案或新增条件先澄清；不必固定只回复字母。

需要改变选择时，直接告诉 Codex。明确指定的新行为和适用范围会直接记入新版本，无需再回复一次字母；如果还在讨论或范围不清，Codex 会先澄清。重复确认相同选择沿用原版本，旧选择和相关代码位置保留，便于检查需要调整的实现。

## 暂停、切换和恢复

你可以先讨论方案、回复“暂缓”，也可以转去处理其他任务。切换任务不会确认原卡。恢复时上下文保留已答、待答和暂缓项：继续有效原卡，已答的不重复确认，暂缓项由 Codex 判断何时需要处理。查询或重复激活不延长卡片有效期。

卡片过期、方案发生修订或另一张卡替代了当前卡后，应根据重新展示的卡片回答。迟到的 A / B 不会确认过期版本。Hook 未启用或未取得信任时，仍可正常交流，但相关选择不能标为已核验。安装问题见[故障排查](TROUBLESHOOTING.md)。

## 查看已做的决定

可以要求 Codex“列出这个任务已确认的选择及相关代码”。代码关联为可选功能，只接受当前真实已确认的决定，保存文件位置与哈希；修订或文件变化后提示复核。不要求每次开发登记，也不分析 Diff 或代码语义，不代表测试通过。

也可以说“把项目决定整理成文档”。默认可先预览，再保存到 BUILDCHOICE_DECISIONS.md，内容包括选择、范围、待办和修订差异；已有手写文档不会被覆盖。文件变化只提示引用待复核，原选择仍保留。详见[上下文与决策文档](CONTEXT_WORKFLOW.md)。

通过明确指令保存决定时，会同时维护当前项目决定的生成文档；同名手写文件保留，改用单独的生成文件。文件暂时无法写入时会说明“决定已保存，文档待同步”，稍后可补写。新聊天会先读取项目记忆，再结合生成文档恢复。

需要检查是否落实时，由 Codex 使用原生测试并解释结果。BuildChoice 不默认启动独立验收/验证流程，不提供独立需求认证。资料读取优先使用[真实工具读取记录](PROJECT_READS.md)。

希望后续聊天继续参考已确认选择时，使用[项目决策记忆](DECISION_MEMORY.md)。遗忘会停止主动召回，原历史仍保留。

## 数据和权限

记录保存在当前项目的 .buildchoice_audit/ledger.sqlite3，不由插件自动上传。记录包括选项、版本、消息摘要、相关来源及检查结果，不保存完整聊天。需要解释的当前卡片回复会在内部保留必要原话；明确修改指令保存引用片段和解释，用于追溯来源。

BuildChoice 的选择记录不替代 Codex 对文件、网络、发布或命令执行的权限审批。候选识别依赖当前 Agent 和已读取资料，不能保证发现所有重要选择。

需要对接工具时，参见[MCP 接口](API.md)。
