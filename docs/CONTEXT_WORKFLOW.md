# BuildChoice · 职责、上下文与恢复

BuildChoice 将判断交给当前 Codex，将可重复核对的事实和状态交给程序。无需增加模型或独立审核轮次。

## 各自负责什么

| 当前 Codex / LLM | 程序 |
|---|---|
| 识别重要选择、解释产品后果 | 检查字段、类型、枚举及选项标识 |
| 判断资料适用性、语义同义与业务冲突 | 核对精确引用、JSON 定位、文件哈希 |
| 建议询问、补查、暂缓或继续 | 单卡、版本、事务、幂等和恢复 |
| 理解自然语言选择和修改范围 | 绑定真实消息、选项或指令与当前版本，标明解释来源 |
| 判断文件变化是否影响原方案 | 返回变化的文件、状态和结构化字段 |

LLM 用 `suggested_action` 提交处理建议，程序另外返回 `validation_status`。引用无效时需要先补查；程序不按风险词、严重程度或依赖词替用户作业务判断。原确认不会因文件哈希变化而消失。

## 一次取得所需上下文

开发前优先调用 `buildchoice_context`，在一次响应中取得当前聊天的已答、待答和暂缓项、项目记忆，以及指定文件的实际内容和来源。例：

```json
{"session_handle":"实际 Hook 句柄","query":"小票保存","paths":["README.md","src/receipt.py"],"max_chars":12000}
```

指定路径会真实读取文件，无需先创建审计会话。同一聊天的完整读取记录、上下文来源和已绑定决策的审计来源，在文件版本有效时可复用。部分读取仍只支持原返回范围；需要全文时由上下文工具重新读取。

响应受 `max_chars` 限制，省略和截断会明确标记。不能将未返回内容当作已读。可缩小查询或路径范围再次取得资料，不要求全仓库扫描。

保存返回的 `snapshot_id`，下一次用 `since` 传入，便可取得文件、决策与记忆状态的字面变化。快照限当前项目和聊天，最多保留最近 100 份；过期后重新取得上下文即可。业务影响由 Codex 判断。

## 避免重复与恢复中断

恢复时先看返回的状态：

- 已答：沿用记录并核对当前范围，避免重复确认。
- 待答：继续原卡；上下文查询不会重新激活或延长卡片有效期。
- 暂缓：等待 Codex 判断当前开发是否已依赖此选择，不自动重开。
- 过期：用当前句柄重新展示有效卡后再接受选择，迟到回复不会确认旧卡。

相同任务中的候选保留稳定 `decision_key`。重复筛选会返回处理标记；同一激活卡换幂等键重试仍沿用原卡，回答不会重复写入。其他聊天可检索项目记忆，不能接管原聊天的待答任务。

## 自然语言回复

明确字母、序号等可直接解析的回复记录为 `user_message_observed`。对于“采用核对后保存，请继续完成页面”等复合表达，Codex 可用 `buildchoice_reply_interpret` 提交本轮原话片段、选项和解释，记录为 `llm_interpreted_user_reply`。

程序核对原话确实出自当前用户消息、卡片未过期且版本与选项未变；不宣称验证了语义。问句、否定、多方案或新条件由 Codex 先澄清。这些选择记录不替代宿主的文件、命令、网络等操作许可。

如果用户已经明确指定行为或修改范围，使用 `buildchoice_record_instruction`，无需先显示卡片。Codex 提交本轮完整原话、引用片段、解释和当前版本；程序核对来源哈希、归属与版本后记录 `llm_interpreted_user_instruction`。新行为追加版本，相同选择的再次确认保留原版本。一个决定可通过结构化取值表达不同范围，例如普通账本自动入账、旅行账本核对后保存；范围解释仍由 Codex 负责。

## 可读决策文档

在对话中说“把项目决定整理成文档”或“列出这次修改前后的选择”。Codex 可调用 `buildchoice_decision_document`：默认返回预览；`write=true` 写入项目的 `BUILDCHOICE_DECISIONS.md`，也可指定已有目录中的其他 Markdown 路径。

文档列出当前选择、适用范围、确认来源、待办项、版本差异和需要复核的引用。修订差异是字段比较，由 Codex 解释业务影响。工具只覆盖自己生成并带标记的文档，拒绝覆盖用户手写文件，也不会改变确认或长期规则。

明确指令的记账会自动维护一份项目当前已确认决定的生成文档。账本和待补写记录先在同一事务中保存，再替换生成文件；文件失败不撤销已经保存的决定，返回 pending。重试原指令请求或写入 decision_document 可补齐，旧回执不会回退新版本。context.document 返回文件路径与同步状态。原有卡片流程发生后续变化时也会显示投影待更新，按需写入文档即可，不在每次调用后自动写文件。

默认不重新展示已遗忘、归档或被修订替代的记忆；明确需要时可包含这些历史记录。接口参数见 [MCP 接口](https://github.com/a853255726-liu/BuildChoice/blob/main/docs/API.md)。
