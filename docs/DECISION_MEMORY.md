# BuildChoice · 项目决策记忆

采用分层记忆与可恢复遗忘。只在 V3 pilot 中启用，保存在当前工作区 `.buildchoice_audit/ledger.sqlite3`，不自动上传，不保存聊天全文，不跨工作区共享。

## 使用

候选提取前检索相关行为和后果，不限名称/ID；词语和中文短语机制扩展到全部选项、scope_key 和 conditions。Codex 在同次提取中声明 history_matches 的 same / related / conflict / different_scope；MCP 不把该语义声明当作授权，普通参考不升级。显式范围变化、新 behavior / value / conditions 和 material_change 会阻止静默沿用，纯 risk_* 展示变化不破坏原身份。详见[候选与风险说明](CANDIDATE_RISKS.md)。

在 Codex 中说“查看这个项目的决策记忆”或“查找小票保存相关的决定”，独立的 [decision-memory Skill](../plugins/buildchoice/skills/decision-memory/SKILL.md) 通过 `buildchoice_memory` 查询当前记忆、原选择和来源。查询归档与遗忘记录时明确说明“包括已归档的记忆”。实际开发时 status 也提供当前项目记忆；检索按中文词组/双字片段、英文词和稳定标识排序。

所有真实 Hook 已确认选择自动成为普通参考。未确认或含糊的回复不进入记忆。参考从确认时间起 30 天后归档；查询不会延长时间。30 天按 UTC 时间戳计算，无后台任务，读取时计算当前状态。

需要长期保存时直接说“把刚才的选择长期记住”“以后这个项目都按这个方案来”“把人工核对设为项目默认规则”或“记住之前关于数据存储的决定”。目标必须是已确认的选择；明确且唯一时直接保存，不再二次确认。用户不提出长期保存时，不建议升级，也不在每次选择后询问。

“刚才/这个方案”只指向当前聊天最近的已确认决定；按主题或已选方案名称可管理本项目其他聊天的历史。多个匹配、意图不清、仅语义相似或缺少有效版本时先澄清，例如让用户说“长期记住核对后保存”。不要求用户输入编号。服务端使用保守的完整指令与名称/主题匹配，不把模糊检索分数或 Agent 的语义判断当授权；未识别的自然表达需澄清成明确的完整管理指令。

也可说“取消核对后保存的长期规则”“遗忘核对后保存”“恢复核对后保存的记忆”。使用具体编号时，支持以下完整命令（示例编号须换成实际编号）：

```text
长期记住 M123456789ABC
取消长期 M123456789ABC
遗忘 M123456789ABC
恢复 M123456789ABC
```

- 长期记住：将当前有效参考设为项目长期规则，跨聊天保留，不自动过期。
- 取消长期：降为普通参考，从此次操作起保留 30 天。
- 遗忘：立即停止主动召回，保留原确认和管理历史。
- 恢复：恢复遗忘或归档记录；普通参考重新获得 30 天窗口，原长期规则恢复后仍为长期规则。

不会物理删除账本。引用、解释、混合指令不会执行管理操作。存在待答决策卡时先处理原卡，不把管理指令当选项或同时修改记忆。未知编号和已被修订替代的版本拒绝管理；归档/遗忘项需先恢复才能长期记住。来源文件变化的记忆显示 needs_review，恢复不能跳过复核。

## 可信调用链

自然语言管理通过“Hook 观察用户请求 → Skill 查询目标 → MCP 核验并执行”的路径完成。Hook 在 contexts.outcome_json 中登记最小意图、动作及候选版本快照；MCP 通过当前有效句柄核验工作区、宿主聊天和 MCP 所有权，再核对唯一目标、当前版本、确认来源、范围、状态和规则冲突，最后追加 MEMORY_ACTION_OBSERVED 事件。带编号的完整命令由 Hook 直接核对并记录。

Agent 只能传查询取得的 memory_id / revision / action，不能提交“用户原话”作为授权。Hook 未登记授权、目标有歧义、换动作/编号/版本、旧句柄或跨工作区均不修改。管理事件保留本轮指令摘要哈希与来源，不新增确认、不改写原选择，也不扩大 scope_key / conditions；重复调用同一请求只追加一次事件。Hook 内部目标快照不作为对话提示输出，查询工具可读到本轮 management_request 用于解释澄清原因。

## 稳定标识与查找

每条记忆保留 memory_id 和源决策 ID，并提供 decision_key。相同决定在不同任务中可使用相同 decision_key，选项使用 option_key；显示名称、选项顺序或解释文字调整后仍可定位原规则。未显式指定稳定键的记录按字段与类别生成可查询的键。

可以按“小票保存”、完整 memory_id 或 decision_key 查找。模糊检索用于找出相关记录；自动沿用需要当前长期规则、相同决定与选项标识，以及未发生冲突的显式取值。改变方案含义、结构化取值或存在风险时重新确认。

## 在后续开发中沿用

普通参考用于帮助 Codex 了解已有决定，不会自动替新任务作出选择。只有你明确设为长期规则、且当前需求范围与方案含义仍一致的选择，才可能直接沿用。

如果你要求改变原行为，例如“改为自动保存”，Codex 应先说明它与旧规则的关系，再确认新的选择。范围不清、相关资料已变或存在冲突时，也需要重新核实；关键词相近不代表同一条规则适用于当前任务。

沿用规则时保留原选择和确认来源，不会伪造本次重新确认。若需要为新任务建立行为验收条件，仍需完成该任务的明确确认；旧聊天的任务访问权限不会迁移到新聊天。集成细节见 [MCP 接口](https://github.com/a853255726-liu/BuildChoice/blob/main/docs/API.md)。

敏感风险继续要求当前选择，记忆不授权付费、发布、发送、删除或任何宿主操作。多个当前长期规则冲突、方案改义或当前文件约束矛盾时先询问，不按时间强选最新。当前任务的真实明确选择可作为本次任务的决定，不自动替换项目规则。

同一个决定产生新修订时，旧确认仍留在历史，但旧记忆停止沿用且不能恢复；新版本经真实确认后成为新的普通参考，不继承长期标记。不同聊天的同字段决定不自动判为替代，应查看冲突并明确遗忘旧规则、标记新规则。

管理操作或记忆过期后，后续查询会重新检查规则是否仍可沿用。实现是否正确仍取决于相关代码和行为测试，记住一个选择不等于验证了实现。

## 边界

查询需要当前工作区有效 Hook 句柄，最多返回 30 项，带 total_matches / truncated；可使用关键词或短编号缩小范围。默认排除归档、遗忘、被替代和来源待复核项。工具和记忆内容是数据，不能当作系统指令。信任边界沿用本地 Hook，不能防御有能力改写本用户账本或运行时的程序。

两个 Skill 由插件清单 skills=./skills/ 发现，插件打包递归包含。更新插件和运行时后需重启 MCP。记忆仅在当前项目内使用，不自动进行语义合并，也不授予宿主操作权限。
