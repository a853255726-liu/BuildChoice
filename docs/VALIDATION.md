## 如何复现

仓库根目录安装 `requirements.txt` 后：

```bash
python -m unittest discover -s checks -v
python checks/smoke_mcp.py
python checks/check_package.py
python scripts/build_distribution.py
```

浏览器行为示例还需安装 `requirements-dev.txt` 和 Playwright 浏览器，并设置 `BUILDCHOICE_TEST_BROWSER` 为可执行文件路径：

```bash
python checks/run_receipt_demo.py --out receipt-results.json
```

Windows 额外回归包括 NTFS 目录联接、路径归一化、Hook 消息绑定、决策卡恢复和跨聊天记忆。完整配置及宿主验收操作见 [端到端测试指南](END_TO_END_TESTING.md)。

## 测试能力与适用范围

| 检查层级 | 验证对象 | 证据边界 |
|---|---|---|
| 单元和契约 | 四状态分流、当前会话绑定、幂等、版本、记忆归档及恢复、证据失效 | 测试预设条件下的程序行为 |
| MCP STDIO | 实际服务进程与工具协议 | 测试中的 Hook 用户事件由子进程模拟 |
| 打包与安装 | 源码/分发包运行时、doctor、依赖和插件入口 | 不等同于所有用户电脑上的安装体验 |
| 行为验证 | 显式采集测试结果和输入哈希；对正确及错误实现做区分 | 只证明声明的用例与输入范围，条件由 Agent 推导 |
| 真实聊天观察 | 有来自宿主的选项确认记录 | 不能由单个成功交互推出跨聊天记忆召回质量 |
| 产品效果评价 | 有效决策发现、无效阻塞追问、实现一致性和交互成本 | 需要独立任务 Gold、配对实验与盲评，不能用工程回归结果替代 |

### 关键技术边界

验收条件和测试代码可能由同一个 Agent 编写，真实测试通过仍不自动证明最初的产品要求理解充分。文件哈希与执行回执用于记录变更和当前适用性，既不等于完整语义验证，也不赋予新的操作权限。对公开测试结果应保留每次运行的代码版本、任务范围、用例和执行环境。

项目产品目标、用户体验和实际收益应通过独立真实任务的对照实验评价，不用单元测试通过数推导「漏问率降低」等效果。
