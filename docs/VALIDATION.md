验收/验证单元覆盖实际确认和 Agent 推导分级、过期句柄/跨会话/旧 revision 拒绝、条件版本与幂等、MCP 不执行命令、无测试/零测试/跳过/未映射用例不通过、失败断言、启动错误/超时、伪造 stdout/报告、报告篡改/缺失、执行中改输入、代码/测试/配置/清单/环境/运行时变化、决定与条件修订、真实代码引用及旧账本回退。额外回归同大小/同时间戳源码与旧字节码缓存，不允许复用旧通过。

`check_package.py` 检查 Python 语法、本地文档链接、三份 Schema、无模型导入/资源、ZIP 校验和与逐文件清单；从实际源码和核心运行包分别初始化，运行 doctor、插件 Hook 启动器、采集 CLI 与验证器。安装目标为独立临时目录，不改变用户现有安装或信任。

真实浏览器示例另装 `requirements-dev.txt` 并设置 `BUILDCHOICE_TEST_BROWSER` 后执行 `python checks/run_receipt_demo.py --out receipt-results.json`。同一套四项用例通过实际点击、字段编辑及 localStorage 观察，区分正确实现、提前入账和忽略修改；分别预期 passed、failed、failed。正确与错误版本的验收条件和测试断言保持相同，仅修改受控配置。输入是合成识别结果，不验证相机、OCR、后端或真实小程序平台。详见 [示例说明](../examples/receipt_review/README.md)。

安装自检测试包括缺失绑定、缺失依赖、工作区不匹配和宿主状态未知。实际宿主插件/Hook 信任检查仍需在目标安装中通过 --host 执行，模拟返回不视为真实宿主验收。检查只写独立临时工作区，不修改用户插件安装或宿主 Hook 信任；临时记录保留以便检查，可用 BUILDCHOICE_CHECK_ROOT 指定父目录。

上述检查验证本地实现与协议，未进行实际 Codex 插件安装或真实用户任务评测。它们不证明漏问率、误问率或打断次数已经下降。coverage 是 Agent 声明；即使来源引用有效也不代表没有遗漏。
